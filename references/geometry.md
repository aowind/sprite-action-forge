# 帧几何：对齐算法与判据

> 这一节解决的核心问题是「**人物只显示一半 / 切动作时变大变小 / 脚悬空**」。
> 三个都是同一个根源：**帧几何没算对**。

## 一、为什么必须做对齐

模型生成的每一帧里，人物的位置和大小都会**漂移**（提示词、参考图都治不好，实测过）。
不对齐的话，整段动画看起来像"角色在画面上蹦来蹦去"。

**唯一有效的是后处理**：逐帧测主体包围盒 → 统一基准 → 在一张更宽的画布上重排。

## 二、四个必须做对的地方（每条都踩过）

### 1. 整段统一缩放（跨动作人物等高）

按**内容高度中位数**把主体归一到目标占比（默认 0.78），**整段只用一个系数** ——
这样呼吸/起伏这类帧间高低变化被保留，而不同动作之间的显示尺寸一致。

```
k = (content_ratio * H0) / median(各帧内容高)
```

> 为什么不是逐帧归一：逐帧把每帧缩到同样高，会把"呼吸"这种高度变化也一起抹平。

### 2. 画布尺寸由内容实际伸展范围**反推**

```
L = max(ref_i - bbox_i.left)      # 内容相对锚点向左最远伸多少
R = max(bbox_i.right - ref_i)
U = max(base - bbox_i.top)        # base = 脚底中位数
D = max(bbox_i.bottom - base)

W = (L + R) / (1 - 2*pad_frac_x)  # 水平：内容占帧宽的 88%
H = (U + D) / content_ratio       # 垂直：内容占帧高的 78%
anchor_x  = (W - span_x)/2 + L
baseline_y = (H - span_y)/2 + U   # ← 上下**对称**留白
```

🔴 **不要写成 `baseline_y = H * U / span_y`**。
当 `D = 0`（脚底从不低于中位数）时，基线会正好落在画布**最底边**，底边距为 0 ——
实测 23 帧全部贴边被裁。

🔴 **不要**先把内容中心对齐到画布坐标 `cx`。画布宽按 `cx ± half_w` 算、原点却在 0，
内容中心落不到 `W/2` → 超出部分直接裁掉（这就是"人只显示一半"的根因）。

这套公式**数学上保证**内容落在 `[pad, W-pad] × [pad, H-pad]` 内，不是试出来的。

### 3. 脚底对齐用**整段同一个 dy**

```python
dy = round(baseline_y - base)     # 所有帧都用这一个值
```

> 逐帧对齐脚底（`dy_i = baseline - bbox_i.bottom`）会把**跳跃/腾空的高度差压平** ——
> 跳起来的帧会被硬拽回地面。整段平移只统一基准，帧间相对高度完整保留。

### 4. `center` 按动作类型区分 —— 这一条最容易搞错

| 动作类型 | 水平对齐 | 为什么 |
|---|---|---|
| 循环类（站立/走/跑） | **逐帧**居中到内容中心 | 原地跑，消掉残余漂移；不消的话看着像在蹦 |
| 一次性类（攻击/技能/挨打） | **整段平移**（用原图中心当锚） | 这些动作**本来就要位移**（前冲、踉跄）。逐帧居中会把位移压平、动作就废了 |

```python
refs = [内容中心 for 循环类]  or  [帧宽/2 for 一次性类]
```

## 三、选窗（loop window）

首尾帧生视频出的是一条"**有开头有结尾**"的镜头，两端带起停包络。
循环动作要取**中段**那段速度稳定的窗口：*起止落在两端，循环来自中段*。

**质量分** = 接缝差 ÷ 窗内差分均值：

| score | 判断 |
|---|---|
| < 0.5 | 干净 ✅ |
| 0.5 ~ 0.8 | 看一眼 ⚠️ |
| > 0.8 | 步幅超出窗 ❌ —— 加长 `--seconds` 或扩大搜索范围重新选 |

一次性动作用"离静止姿势最远"的**活动窗**；要避开运动拖尾时用 **`tail` 模式**取尾段。

## 四、拼表

- 单帧等比缩放到统一帧高，横向拼接
- **总宽 = 单帧宽 × 帧数**，注意别顶穿 GPU 纹理上限（脚本内置 8000 的拒绝线）
- 输出 WebP（无损 PNG 动辄 9MB/张）

## 五、输出给游戏的两个关键比例

| 字段 | 含义 | 游戏怎么用 |
|---|---|---|
| `content_h_ratio` | 人物高 ÷ 单元格高 | 反推帧显示高度：`frameH = charH / content_h_ratio` |
| `baseline_ratio` | 脚底线 ÷ 单元格高 | 把脚底钉在路面线上：`dy = roadY - frameH * baseline_ratio` |

🔴 这两个值**在装配时从最终 webp 重新量**（`install_sheets.py` 的 `measure_sheet()`），
不要直接信生成时的 meta —— 素材会被重生成/回退，一旦不一致，
游戏就按错误的尺寸与基线画。

## 六、自检

对齐函数末尾自带复核：重新测一遍整理后的帧，任何一帧贴到边界就打印

```
⚠️ 对齐后有 N 帧贴边（可能被裁）—— 检查 align_frames
```

看到这行就说明几何算错了，别忽略。
