# 游戏侧接入：状态机、招式时序、位移、特效叠加

> 这套是"素材做好了怎么真正用起来"的部分。
> 三条最容易错的先列在这里：**触发判上升沿**、**出手要挂起**、**时长从素材推导**。

---

## 一、动作状态机

### 数据流

```
战斗层（规则）                     表现层（时序/绘制）
  u.hurtT / u.lungeT  ──脉冲──▶   AnimState.step()  → 当前动作名
  u.pending（招式挂起）──事件──▶   windup / damage  → 切动作、叠特效
                                  meta(frames/fps)  ──时长──▶ 回注战斗层
```

**时长必须两边同一份**（都来自素材 `帧数/fps`），出手与结算才会严格对齐。

### 🔴 触发一律判「上升沿」，不能判电平

```js
// ❌ 错：只要 skillT 没倒计时完，每一帧都重置 this.t = 0
else if (this.skillT > 0) trig = 'skill';

// ✅ 对：只在 0 → >0 那一帧触发
const skillEdge = this._pSkill <= 0 && this.skillT > 0;
...
this._pSkill = this.skillT;          // 先记上一帧
this.skillT = Math.max(0, this.skillT - dt);
```

踩过的后果：技能动画被**死死钉在第 0 帧**，永远不往前播。

### 🔴 一次性动作要「锁存」，不能拿脉冲当进度条

战斗层给的出手/受击脉冲只有 0.16~0.26 秒，而攻击动画要 0.6 秒才看得清。
看到上升沿就切进动作，**播满自己的时长再让位**：

```js
if (trig && set[trig]) { this.act = trig; this.t = 0; this.dur = spec.frames / spec.fps; }
else if (isOneShot(this.act)) {
  if (this.t >= this.dur) { this.act = base; this.t = 0; }   // 播完才让位
}
```

**优先级固定**：挨打 > 技能 > 普通攻击。不然挨打瞬间正好自己出手，会播成攻击，反馈是错的。

### 帧号

- 循环动作：`floor(t * fps) % n`（一直转）
- 一次性动作：`min(n-1, floor(t * fps))`（**钳在最后一帧**，播完定格，不会跳回第 0 帧）

### 按 id 各自一份状态

每人/每怪一个 `AnimState`，互不干扰。挂机类项目跑几小时，
**必须定期回收已死实体的状态**，否则 map 只增不减 → 内存泄漏。

## 二、招式时序：**动作播完才结算伤害**

### 症状

"怪物已经死掉、人也退回原位了，技能动作才开始播" —— 时序整个反了。

### 根因

战斗层出手时**立即**算伤害，它不知道动画播到哪；动画只是**事后被动跟随**。
所以玩家看到的是"先出结果、后演过程"。

### 改法：出手「挂起」→ 到点「结算」

**战斗层**
```
_beginStrike(side, actor, payload):
    ① 置起手脉冲（表现层靠这个上升沿切动作）
    ② 发 windup 事件（技能要切"释放技能"动作）
    ③ 记下招式参数（目标 id / 倍率 / 段数 / 技能名）
    —— 这里**不算伤害**

_tickPending(dt):
    p.t += dt
    if p.t >= p.dur: _resolve*Strike(actor, p)   # 这才是真正算伤害的时刻
```

- **消耗 / CD / 减益仍在起手时**处理（不然"动作还在演就能再放一次"）
- `actor.pending` 存在期间**不许再起手**
- `dur` 由表现层注入：`battle.setActionDur({attack, skill})`，值 = 素材 `帧数/fps`
- 结算时目标已死 → 换最近的活目标；怪全没了 → 不结算

**表现层**
- 收到 `windup` 才切"释放技能"动作（**不能放 `damage` 里** —— 那要等到结算才播）
- 收到 `damage` 才是飘字/闪红/死亡的时刻

### 验收判据

试跑并采样，断言：**掉血发生那一刻，动作进度已接近 100%**。

```
[skill] 掉血在起手后 1000ms（掉血前动作进度已达 98%）  挂起记录=true   ✅
```

⚠️ 断"结算有没有提前"要看**掉血前一帧**的进度：结算发生的同一帧里，
下一招可能已经起手、动画被重置，直接读掉血那一帧会读到 1%（读数被污染）。实测踩过。

## 三、攻击位移：由程序做，不画在精灵里

**要求**：角色移动到目标身旁 → 攻击完 → 移动回来。位移**不在精灵动画里**。

```
0 ~ 30%   突进（home → 目标旁）
30 ~ 100% 贴身把招式演完（**期间不能退回**）
动作结束后 0.32s 归位（平滑退回）
```

要点：
- 目标 = 离自己最近的活怪（在我方右侧），停在它左边 `ATK_STAND_GAP` 处
- 单次位移设上限（`ATK_MAX_TRAVEL`），别追远处的怪时一冲半个屏幕
- 归位是**动作之后的独立阶段**，用缓动平滑退回 —— **不要**在动作结束时把位移直接清零
  （那是瞬移回位，看着像被弹走）
- ⚠️ 目标坐标要防 `NaN`（见 `pitfalls.md`）

## 四、特效：独立精灵 + 加法叠加

### 素材侧

- **黑底 + alpha = 亮度**（减 floor 去视频压缩底噪）→ 黑=全透明，亮=不透明，光晕自然半透明
- 位置/缩放/延迟都写在 meta 里（`offset_x/offset_y` 以**人物高**为单位、`scale`、`delay_ratio`）

### 游戏侧

```js
const dur = spec.frames / spec.fps;
const start = (spec.delay_ratio || 0) * anim.dur;   // 特效可以在动作中段才开始播
const t = anim.t - start;
if (t < 0 || t > dur) return;
const idx = min(spec.frames - 1, floor(t / dur * spec.frames));

ctx.globalCompositeOperation = 'lighter';           // 加法：黑底加 0 = 没画
ctx.drawImage(spec.img, idx * fw, 0, fw, fh, px - W/2, py - H/2, W, H);
```

- `delay_ratio`：跟手的（刀光）给 0；要"等招式演到末段才落"的（落雷）给 0.8 ——
  正好和"动作播完才结算伤害"对齐
- `offset` 相对**角色中心 / 脚底基线**，以人物高为单位 —— 换角色尺寸不用改代码

### 验收：A/B 像素对比（最硬的证据）

同一动画状态渲染两次（一次清空特效映射），比像素：

```
带特效 vs 不带特效 → 差 1781 像素，最大加亮 +239   ✅ 特效确实画上去了
```

## 五、被击 / 倒下表现

- 被击`hurt` 走**上升沿锁存 + 最高优先级**（见上）
- **击杀时怪不能瞬间消失**：`alive=false` 后还要画一小段（0.45s）——
  定格在**受击动作最后一帧** + 淡出 + 轻微下沉
  > 踩过：一击必杀时 `if (!alive) continue` → 玩家看不到任何被击反馈。
  > 这一条在"被击动画"的需求里特别容易漏。

## 六、自检清单（接完必跑）

| 检查 | 判据 |
|---|---|
| 清单加载 | 所有角色 key 都在，无 404 |
| 动作切换 | 采样一段时间，主角/怪物各自**出现过哪些动作**都要覆盖到 |
| 帧号推进 | 取值数 > 1（否则是卡死的假动画） |
| 落位 | 脚底在路面线上、跨动作人物等高 |
| 招式时序 | 掉血时动作进度 ≈ 100% |
| 特效 | A/B 像素对比有差异 |
| 报错 | console 无 `pageerror`、无 404 |

> 采样要**条件轮询**（判据满足就返回），别写死"等 N 秒"。
