# 完整流水线（每一步在干什么、为什么）

```
立绘/设定图
   │
 ① 绿幕首帧       flood fill 白/透明底 → 纯绿；裁到主体；摆到 768×768
   │               （顺序：先 flood fill **再**缩放，反过来会引入新的白边）
   ▼
② 本地 H3 出片    ComfyUI + MiniMax H3（首尾帧生视频 FL2VA），2 秒左右
   │               8GB 显存：--lowvram + KJNodes 两个无损压显存节点 + 8 步 Turbo LoRA
   ▼
③ 抽帧            原生 24fps 抽满（后面由选窗决定采样）
   │
 ④ 抠绿            严判据（g 明显高于 max(r,b) 且 g 够亮）+ despill 去绿边
   │               自带体检：主体内部透绿占比
   ▼
⑤ 逐帧对齐        整段统一缩放 + 脚底整段平移 + （按类型）水平逐帧居中或整段平移
   │               画布由内容伸展范围反推 → **算出来不裁**
   ▼
⑥ 选窗            循环：中段稳定窗（质量分）；一次性：活动窗；避开拖尾：尾段窗
   │
 ⑦ 拼表           WebP；总宽 = 单帧宽 × 帧数（防顶穿纹理上限）
   ▼
⑧ 装配           装进 web 目录（**覆盖前强制备份**）+ 生成 actions.json
                 meta 里的比例**从最终素材重量**
```

## 各步骤的输入输出

| 步 | 输入 | 输出 | 关键点 |
|---|---|---|---|
| ① | 立绘（白底/透明底） | `<work>/first_frame.png` | 主体占高 72%、脚底 92%、水平居中 |
| ② | 首帧 + 提示词 | `<work>/clip.mp4` | 循环动作**必须 2 秒** |
| ③ | mp4 | `<work>/_frames/f_*.png` | 需要 ffmpeg |
| ④ | png 序列 | RGBA 帧 | 判据严、宁漏勿误 |
| ⑤ | RGBA 帧 | 对齐后的 RGBA 帧 | **最容易错的一步**，见 `geometry.md` |
| ⑥ | 对齐后的帧 | 帧下标列表 + 质量分 | 循环动作看 score |
| ⑦ | 选中的帧 | `<char>_<action>.webp` | WebP |
| ⑧ | webp + meta | web 目录 + `actions.json` | 备份 + 重量比例 |

## 为什么是"绿幕 + 首帧"这条路

- **首帧生视频（FL2VA）** 让风格、比例、配色与立绘严格一致 —— 不需要重新训练/描述角色
- **绿幕** 是因为纯色背景最容易抠干净；判据可以做得很严（角色身上的暗青绿不会被误伤）
- ⚠️ **不能指望"文生图直接出透明"**：透明背景需要「自带 alpha 的输入图」+ 明确的透明参数，
  链路本质是"生成 → 抠 → 精修边缘"

## 中途重跑很便宜

每一步的中间产物都留在 `<out>/_work/<char>_<action>/`：

- `first_frame.png` — 首帧
- `clip.mp4` — 生成的视频（**只要它还在，就不用再花 GPU 时间**）
- `_frames/` — 抽出的帧

所以调对齐参数、换选窗策略时，加 `--reuse-video` 几秒就能重跑完 ⑤⑥⑦。

## 角色/动作的组织方式

- **角色 id 就是文件名前缀**：`hero` / `mob_boar` / `mob_bandit`
  → 产出 `hero_idle.webp` / `mob_boar_run.webp`，装配零配置
- 一个角色做多个动作：`--actions idle,run,attack,skill,hurt`
- 角色专属提示词：`--prompts prompts.json`（`{action: {prompt/neg/tail}}`）

## 验收（生成侧）

| 检查 | 判据 |
|---|---|
| 抠绿成功帧数 | 接近抽出帧数（差太多说明判据不对） |
| 主体内部透绿 | 接近 0%（高了说明判据太宽、身上抠出洞） |
| 对齐贴边帧 | **0**（有就说明几何算错，会被裁） |
| 循环质量分 | 循环动作 < 0.5 干净 |
| 表宽 | 单帧宽 × 帧数 < 8000 |

生成侧的验收在脚本里自动打印；**接进游戏后的浏览器验收**见 `integration.md` 第六节。
