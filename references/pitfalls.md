# 踩坑清单（按现象查因）

这份是从一个真实项目里一条条踩出来的。**遇到问题先在这里查**，能省掉大量重复试错。

---

## 一、画面/素材类

### 人物只显示一半（缺右半边 / 缺左半边）

**根因**：对齐时把内容裁掉了。

早期实现把"内容中心"对齐到画布坐标 `cx`，而画布宽度是按 `cx ± half_w` 算的、
**坐标原点却在 0** → 内容中心落在 `cx` 而不是 `W/2`，超出画布的部分被直接裁掉。

实测：站立动作 6/6 帧右边缘被切（帧宽只有 168px、内容却占 51.7% 宽）；怪物系全部左边被切。

**修法**：画布尺寸**由内容的实际伸展范围反推**：
```
L = max(各帧 ref - bbox_left),  R = max(bbox_right - ref)
W = (L + R) / (1 - 2*pad_frac)      # 水平：内容占帧宽的 (1-2*pad)
H = (U + D) / content_ratio         # 垂直：内容占帧高的 content_ratio
baseline_y = (H - span_y)/2 + U     # 上下**对称**留白
```
详见 `geometry.md`。算法里自带复核：整理后若有帧贴边，打印告警。

### 人物在攻击/技能那几帧**整个不画**（像消失了）

**根因**：坐标算出了 `NaN`。

链条：找攻击目标时用 `m.x <= home` 过滤怪 —— 而怪刚生成时 `x` 还没写，
`undefined <= home` 是 `false`（**不会**被过滤掉）→ 被选成目标 →
`atkTo = undefined - gap = NaN` → 传到绘制坐标 `cw * (x + NaN) = NaN` →
`drawImage` 在 NaN 坐标上什么都不画。

**修法**：两处都要挡 —— 选目标时 `Number.isFinite(m.x)` 过滤；
绘制前 `const homeX = Number.isFinite(u.x) ? u.x : fallbackX;`。

> 同类教训：**任何从战斗数据算出来的坐标，进 canvas 之前都挡一道 `Number.isFinite`。**

### 切动作时人物突然变大变小

**根因**：拿"帧高"当"人物高"。

各动作的垂直跨度不同（举剑/挥砍会让画面上下都多占），
精灵表里"人物高 ÷ 单调格高"实测在 **0.60~0.78** 之间漂。
游戏按帧高算尺寸 → 每个动作的人物显示大小都不一样。

**修法**：meta 里输出 **`content_h_ratio`（人物高占比）** 和 **`baseline_ratio`（脚底线占比）**，
游戏按它们反推帧高、把基线落在路面线上。

### 脚悬空 / 脚陷进地面

同上，`baseline_ratio` 没被使用，或者用的是生成时的旧 meta（素材已替换）。
**装配时从最终 webp 重新量**，别信 meta。

### 人物被压成一条窄缝

**根因**："帧数"写在游戏代码里，素材换了但常量没改。

**修法**：帧数/帧率一律从 meta/清单读，**不在游戏代码里手写**。
任何"帧数写在代码里"的常量，都是素材替换后的定时炸弹。

### 身上透绿（抠图在角色身上抠出洞）

**根因**：抠绿判据太宽，把角色自带的墨绿/青绿当成幕布了。

**修法**：判据要**严、宁漏勿误** —— 两条一起用：
```
幕布的绿 = (g - max(r,b) > 46) 且 (g > 110)
```
幕布是**纯亮绿**（g≈255, r=b≈0），角色身上是**暗青绿**，第二条能把暗绿排除掉。

**自查工具**：`hole_ratio()` —— 对"非绿"掩膜**填洞**，填不到的透明区才是"身上透绿"。
⚠️ 别用"画面中间一块"或"bbox 矩形"当判据，两者都会虚高（bbox 是矩形、角色是细长条）。

### 边缘有一圈绿光

**根因**：没做 despill（绿幕反光染到角色边缘）。
**修法**：把边缘像素的 g 通道压到和 `max(r,b)` 一个水平。

## 二、生成/提示词类

### 怪物生成出来是"静止插画"（逐帧像素几乎一样）

**根因**：提示词太通用。把「站着呼吸、微微起伏」用在**纸雕四足怪**上，
模型认为这就是一张静态图，直接照抄。

**判据**：对齐后的 `spread_bottom` / `spread_center` 是 **0.0px** = 完全没动。

**修法**：给怪物写**具体到身体部位**的措辞 ——
"胸腹起伏 / 耳朵抖动 / 尾巴左右摆 / 四条腿轮流抬起、蹄子离地 / 獠牙前顶"。
见 `prompts.md` 的怪物措辞表。改后同一动作质量分从 3.81(WEAK) → 0.70。

### 跑步"像滑行"，身体朝向被焊死

**根因**：提示词给的是"原地跑"的通用描述，模型把身体朝向固定了。
**修法**：跑步/走路要**单独写躯干旋转** —— 说明"哪条手臂向前摆，那一侧肩膀就向前送、腰跟着扭"。
角色面朝画面右侧时：左肩向前 → 转向观众、看到更多正面；**右肩向前 → 转过去、看到后背**。

### 快速挥砍/挥剑总会带上运动拖尾（文字禁令压不住）

**硬限制**：模型对快速挥砍**必然**画运动拖尾，而且拖尾是**实心绘制**的
（实测 alpha ≥ 250、占画面 19%）—— 靠 alpha 阈值分不开，改提示词也没用（强化措辞反而更大）。

**三个可用对策**：
1. **改动作设计**：技能改成小幅"举剑蓄力"（不挥砍 → 无拖尾），力量感交给独立特效（落雷）
2. **取尾段选窗**：拖尾只出现在运动段，视频后段（动作定型后）是干净的 → 用 `tail` 模式
3. **多次生成里挑**：装配脚本的 `_backup_public/` 保留了历史版本，是"选哪一版"的依据，**别删**

### 指定"哪条腿/哪只手"模型理解不了

**修法**：用**画面位置**（近侧 / 远侧 / 画面左边），不要用角色的内在左右。
模型能理解"画面上在哪"，理解不了"这是角色的哪一边"。

### 持械的手臂被身体挡住、武器变成小短棍

**修法**：把持械的手臂固定描述成"在**身体侧前方**、器物完整可见"，
别写"在身后"。

### 帧数/落点不受控

**修法**：要精确控制动作就给**参考图**，别指望文字。
实测：文字描述 ❌ / 文字+量化角度 ❌ / **动作框架图并排拼图** ✅。

## 三、工程/环境类

### 动画卡住不动，但背景正常滚动

**两种根因，先看 console 的 `pageerror`**：
1. 主循环某帧抛错（如漏 import 的 `ReferenceError`）→ 表现完全像画面 bug。
   实测踩过：`Cannot access 'fx' before initialization`（`const` 的 TDZ，变量在读之后才声明）
2. **触发判成了"电平"**：`if (skillT > 0) 切动作` —— 只要计时器没归零，
   **每一帧都重置 `anim.t = 0`**，动画被钉死在第 0 帧。必须判 **0 → >0 的上升沿**。

> 自检手法：清空 `window.__idle.charAnims` 之类的东西模拟"meta 加载失败"，
> 不用改文件就能走到回退分支。

### 服务"看起来死了"，其实是并行任务把它带走了

**诊断别只看页面** —— 用 `curl -s -o /dev/null -w '%{http_code}' URL` 一下。
⚠️ **服务死掉时浏览器里所有资源请求都会失败，看起来和"素材缺失/路径写错"一模一样**
（曾据此误判"12 张背景全坏了"，其实文件好好的）。

**修法**：写个"有则复用、无则补起"的自检脚本（`ensure_comfy.sh` 就是），
并且**绝不"先杀占端口的进程再起"** —— 多会话环境下那等于踩掉别人正在跑的服务。

### 后台批处理偶发失败，前台单跑就好

实测遇到过一次：同一命令前台稳定、放进后台循环里偶发裸 `SystemExit(1)`，未定位到根因。
**对策**：批处理里每个任务加重试；关键产出前台跑。

### 素材被覆盖后无法恢复

**教训**：很多项目**不是 git 仓库**。实测踩过：抽帧脚本直接覆盖了在用的跑动表
（23 帧 → 10 帧），而游戏代码里还写着 23，跑动直接坏掉，只能靠别处的同名副本手动捞回来。

**对策**：装配脚本**覆盖前强制备份**到 `_backup_public/<时间戳>__<文件名>`。
这个目录同时是"挑哪一版"的依据，**别删**。

### 精灵表总宽顶穿 GPU 纹理上限

**判据**：单帧宽 × 帧数（常见上限 8192）。实测 10 帧 × 920px = 9200px 已超；
把帧高从 720 降到 480 → 6200px 才安全。
脚本里已内置宽 > 8000 就拒绝并提示调小 `--frame-h`。

### 无损 PNG 太大

交付素材一律走 **WebP**（无损 PNG 动辄 9MB/张）。
